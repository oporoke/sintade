Fixed per [ADR-0005](../adr/0005-minio-image-mirrored-to-ghcr.md): the still-locally-cached image was mirrored to `ghcr.io/oporoke/sintade/minio` (public, pinned tag `RELEASE.2025-09-07T16-13-09Z`); `compose.yml` and `.github/workflows/ci.yml` now pull from there instead. This is a stopgap, not a fix for the underlying trend — MinIO's continued retreat from open source means self-hosted MinIO's long-term viability for this project should be revisited before the V1 media pipeline leans further on it (e.g. bucket-notification webhooks).
- MinIO's official free Docker images moved from Docker Hub to `quay.io/minio/*` (Oct 2025 policy change); `docs/design.md`'s "MinIO bucket CORS" line doesn't apply to the free/community edition (per-bucket CORS is AIStor/paid-only) — CORS is configured server-wide via `MINIO_API_CORS_ALLOW_ORIGIN` instead, which is equivalent for a single-bucket dev setup.
- This sandbox's network cannot download Playwright's own Firefox/WebKit browser binaries locally (`npx playwright install` stalls at 0 bytes on the actual archive download). Not an issue for CI, which has real network access and installs them fine — see Day 9's follow-up row. `web/playwright.config.ts` falls back to the system Chrome (`channel: 'chrome'`) only when the `CI` env var is unset.
- **No staging VPS exists yet.** Day 10's `deploy-staging` CI job (SSH deploy + `sqlx migrate run` against `STAGING_DATABASE_URL` + a `/readyz` smoke test) is a real, wired stub — it will start deploying automatically once a VPS is provisioned and `vars.STAGING_HOST`/`vars.STAGING_SSH_USER`/`secrets.STAGING_SSH_KEY`/`secrets.STAGING_DATABASE_URL` are set in the repo's GitHub settings, and `deploy/compose.prod.yml` is placed at `/opt/sintade/` on that VPS. Until then, Day 10's literal Check ("staging shell loads, /readyz green") cannot be satisfied.
