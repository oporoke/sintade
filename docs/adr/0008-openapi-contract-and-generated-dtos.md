# ADR-0008: OpenAPI contract from utoipa, TS DTOs from openapi-typescript, drift-checked

## Status

Accepted — 2026-09-25

## Context

`docs/design.md` §17 says API DTOs are "generated from the backend OpenAPI spec (`utoipa`) into
`web/src/app/api/`", but doesn't name a TS generator or say how the generated files stay in
sync. Day 19's Check is "Frontend compiles against generated DTOs".

## Decision

- **Spec:** every handler carries `#[utoipa::path]`, and every DTO derives `ToSchema`.
  `bin/api/src/openapi.rs::ApiDoc` lists the paths. `api openapi` prints the spec without
  loading config or touching the database. A unit test fails if any route in
  `routes::table()` is missing from `ApiDoc`.
- **Committed artifacts:** `docs/api/openapi.json` (the contract, reviewable in PRs) and
  `web/src/app/api/schema.ts` (types only, no runtime code). Both are regenerated by
  `just openapi`.
- **Generator:** `openapi-typescript` 7.13.0, pinned as a devDependency, chosen with the user
  over openapi-generator (heavier, Java, would duplicate `ApiClient`) and a hand-written
  script. Its peer range is `typescript ^5`; an npm `overrides` entry points it at the
  project's TS 6. The output was byte-identical to a standalone `npx` run, which resolves its
  own TypeScript.
- **Frontend usage:** `core/auth.models.ts` only aliases `components['schemas'][...]`. Request
  bodies use `satisfies` / typed locals, so a renamed or removed field is a compile error,
  including inside templates (`strictTemplates`).
- **Drift:** `just openapi-check` (part of `just check`) and CI's `contract` job regenerate
  both files and `diff` them against the committed copies; the CI job then runs
  `npm run build`. The generated file is excluded from ESLint.
- **Kernel stays API-free:** `kernel::Role` and the `Id<T>` newtypes get no utoipa derive.
  The API layer maps them to DTOs (`MemberRole`; `#[schema(value_type = uuid::Uuid)]`).

## Consequences

- Changing a Rust DTO without running `just openapi` fails `just check` locally and the
  `contract` job in CI.
- A DTO change that breaks the frontend fails the build. This was verified by renaming
  `MeUser.email`: the `home` and `profile` templates both failed to compile.
